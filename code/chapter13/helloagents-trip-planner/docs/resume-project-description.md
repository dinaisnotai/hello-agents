# 智能旅行规划助手：简历项目描述

本页只使用仓库中已经实现和验证过的能力。项目不接入真实预订或支付；门票、酒店和交通报价均明确标注来源和不确定性。

## 一句话描述

> 面向多约束出行规划的全栈 Agent 应用：通过 LangGraph 编排景点、酒店、天气查询 Agent，以高德地图 POI/路径作为事实来源，结合确定性空间规划、事务式质量修复和可追溯 RAG 证据，生成支持对话重规划的每日行程。

## 简历精简版（推荐，4 条）

```text
智能旅行规划助手 | Python / FastAPI / Vue 3 / TypeScript / LangGraph / SQLite / 高德地图 API / Embedding RAG

- 设计 LangGraph 旅行规划工作流，编排景点、酒店、天气 3 个查询 Agent 与 LLM 体验审查；将路线、预算、步行、营业时间等可验证事实收敛到确定性规划器，模型不可用时可降级执行。
- 实现基于 POI 坐标的空间分天与混合交通规划，接入高德地点详情、周边检索和路径服务；按景区父级 POI 与用户必去点语义去重，避免把圆明园等景区内部区域重复排入行程。
- 构建约束质量门与有界事务式修复：对非景点、非餐饮 POI、重复游览、超时、预算、步行和下午过早晚餐进行校验；修复在深拷贝沙箱中执行，仅在目标问题改善且未引入新硬约束时提交，并记录版本、变更范围和回滚原因。
- 实现 SQLite 会话/版本历史与对话重规划接口；构建 Hybrid RAG（关键词 + Embedding）作为可追溯攻略证据，并完成 210 项离线回归测试及 Vue 生产构建验证。
```

## 详细版（投 AI 应用工程 / Python 后端）

```text
智能旅行规划助手 | Python / FastAPI / Pydantic / LangGraph / Vue 3 / TypeScript / SQLite / 高德地图 API / HelloAgents LLM / Embedding RAG

- 设计“Agent 查询策略 + 确定性规划决策”分层架构：景点、酒店、天气 Agent 负责生成查询方向和风险解释，地图服务负责 POI 身份、坐标、周边餐饮和路径事实，避免将距离、预算和营业时间计算交给 LLM。
- 基于 LangGraph 编排查询、候选扩展、规划、验证和有界修复节点；为每次运行记录候选、约束、质量问题、修复尝试和最终状态，支持 simple/legacy 工作流降级以隔离外部服务故障。
- 实现 POI 身份解析与候选治理：利用 provider ID、parent POI ID、名称和坐标合并别名；对用户必去景点增加“主景区—内部区域”语义去重，并过滤医院、充电站、交通设施等不能占用景点或正餐名额的地点。
- 实现空间分天、景点排序与混合交通选择，使用真实路径替代直线距离估算；根据酒店—首末景点往返路线复核酒店位置，并对午餐、晚餐分别按景点出口和酒店周边 POI 搜索，保留餐饮类型、菜系方向和来源字段。
- 设计 Itinerary Completeness Gate 与 RepairController：校验必去点、重复、开放时间、步行、交通、预算、偏好、餐饮身份和日程时间轴；修复候选在深拷贝沙箱中重新计算并比较质量分，只接受未新增硬约束的变更，保留审计轨迹与回滚理由。
- 构建 Hybrid RAG 检索链路，按游览、住宿、交通、餐饮拆分检索目的，融合关键词与向量召回并返回证据来源；因数值投影在覆盖率回归中退化，当前将 RAG 限制为解释和可追溯证据，而不直接替代地图或约束决策。
- 实现 SQLite 持久化会话、计划版本、聊天消息及增量重规划；前端展示路线分段、餐厅、价格状态、未满足约束、休息缓冲和质量问题。完成 210 项离线回归测试与 `vue-tsc && vite build` 验证。
```

## 面试时的 40 秒讲法

> 这是一个多约束旅行规划项目。早期我发现只靠 Agent 和 RAG 会生成重复景点、把充电站当餐厅，或者看似满足预算但路线无法执行，所以我把系统改成两层：LLM 和三个查询 Agent 只负责查询策略、风险解释和体验审查；高德 POI、路线和确定性规划器负责事实与硬约束。规划后会进入质量门，修复在深拷贝沙箱里重新算路线、预算和质量，只在没有新增硬问题时提交。RAG 现在负责提供可追溯攻略证据，数值投影因为回归集退化没有强行上线。这个取舍让我能解释每个模块实际影响了什么，也避免把模型输出当作事实。

## 不能这样写

- 不写“实现真实预订、实时票务价格或准确交通票价”：项目目前提供的是来源明确的规划估算和待核实提示。
- 不写“RAG 显著提升准确率”或“向量检索驱动景点排序”：当前 RAG 的自动数值投影关闭，原因是覆盖率回归。
- 不写“LLM 自动解决全部问题”：LLM 是受结构化合同约束的审查层，确定性质量门和地图事实才是执行边界。
